# 数据源开发指南

> M2-P3 交付（设计 附录B 摘要版 / 3.2 / 3.9 / 3.10）。新增数据源的接入模板。

## 数据流总览

```text
远程源(akshare/tushare/baostock…) → RemoteKlineSource.fetch_kline
        → DataFetcher 六步管道（覆盖→增量→归一校验→DuckDB 去重→原子落盘→缓存失效）
        → data/kline/{type}/day/{code}.csv（tushare 源格式原始列, 3.12 raw 精神）
        → CsvSourceDriver 读取 + DataNormalizer 归一（下载与回测同一条归一链路, 3.3）
```

## 1. 建包与协议

```text
mtzquant/data/drivers/<name>_driver.py     # 远程源驱动
```

实现 `RemoteKlineSource` 协议（`mtzquant/data/drivers/remote.py`）：

```python
class MySource:
    name = "mysource"
    def fetch_kline(self, code, start, end, *, instrument_type) -> pd.DataFrame:
        """返回 tushare 源格式原始列（ts_code/trade_date/open/high/low/close/vol/amount, 3.5）。"""
    def fetch_master(self, instrument_type=None) -> pd.DataFrame:
        """返回主数据原始列（ts_code/name/list_date/…, 3.11）。"""
```

输出**原始格式**即可（列名/代码/时间戳交给 DataNormalizer），但需保证：
**升序、无重复时间戳、币种单位一致**（附录B）。

## 2. 注册

```python
from mtzquant.data.drivers.remote import register_source
register_source("mysource", MySource)
```

注册后 `DataFetcher(sources=["mysource", "akshare"])` 多源 fallback 自动生效（顺序=fallback）。
`fetch_master_once` 与 `_map_master_rows` 复用（代码归一/upsert 由 fetcher 承担）。

## 3. 限流与防封禁（3.9）

接入 `RateLimitController`（`mtzquant/data/ratelimit.py`）——每源令牌桶 + 抖动 + 自动降档
+ 熔断。在 `mtzquant/data/ratelimit.py::SOURCE_RATES` 登记基础速率：

```python
SOURCE_RATES["mysource"] = RateSpec(rate_per_min=120)   # 官方接口限频
```

重试走 `RetryPolicy`（指数退避 2^n × 抖动）；封禁类响应（积分不足/黑名单）**抛结构化
错误不重试**（`_is_rate_limited` 命中限流则降档）。

## 5. 数据质量与体检（3.10）

落盘前 `DataFetcher` 自动：
- 覆盖检查（`CoverageChecker.gaps`: 交易日 gaps, 日历优先退化周一~五, 幂等）;
- 归一校验（`DataNormalizer` 复用, 3.3）——不可归一则拒绝写盘;
- 重复 dt 拒绝写盘（3.9 c, 原文件完好）;
- DuckDB 去重合并（`UNION ALL` + `row_number`, keep=latest/first 可配）;
- 原子落盘（临时文件 + os.replace）。

人工体检：`mtzquant sql "SELECT ..."`（只读守卫）或 `DuckDBQuery.quality_report`
（缺失交易日/0价0量/OHLC 越界/重复日期/日期解析失败模板）。

## 6. 大数据源（分钟/tick, M5）

实现 `load_kline` 的同时声明 `supports_parquet_cache=True` 以复用二级缓存
（`mtzquant/data/cache.py`, 3.7）；分钟线 fetch 归 M5（pyproject marker `m5_deferred`）。
