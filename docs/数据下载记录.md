## 1. 前提

- Python ≥ 3.11，项目已按 `docs/使用说明.md` §1 装好 `.venv` 与核心依赖。
- 一个 **tushare 账号 token**（https://tushare.pro 注册后个人主页获取；积分越高，单次可拉取历史越长、限流越宽松）。

---

## 2. 第 0 步：准备环境与 token

### 2.1 安装 tushare（可选依赖 download 组）

tushare 属于可选依赖，未随核心安装：

```bash
.venv/Scripts/pip install "tushare>=1.4"
```

> 只下载数据只需 tushare；若要用 akshare 做多源 fallback，可装整组：
> `.venv/Scripts/pip install -e ".[download]"`

### 2.2 配置 token（密钥纪律：只进 secrets.json，不入库）

```bash
cp config/secrets.example.json config/secrets.json
# 打开 secrets.json，把 token 填入：
#   { "tushare": { "token": "你的token" } }
```

token 读取优先级（`mtzquant/config.py`）：环境变量 `MTZQUANT_TUSHARE_TOKEN` > `config/secrets.json` 的 `tushare.token`。

### 2.3 确认数据根目录

默认根目录是 `./data`（仓库根，`.gitignore` 已锚定 `/data/` 排除提交）。如需改路径，编辑 `config/settings.json`：

```jsonc
{ "data": { "local_csv": { "root_path": "./data" } } }
```

> 建议直接用默认 `data/`：`mtzquant run`、`fetch`、测试默认都指向它，零额外配置。

## 3. 第 1 步：认识数据目录约定（设计 3.12）

下载只产生两种文件：

```text
data/
├── master/instruments.csv        # 标的主数据（代码/名称/类型/交易所），下载时自动 upsert
└── kline/{type}/day/{code}.csv   # 日线，按品种分目录：
                                  #   etf/   → 场内基金（ETF + LOF，代码 5/159/16 开头）
                                  #   stock/ → 股票
                                  #   index/ → 指数（基准，不可交易）
```

**文件格式 = tushare 源格式原始列**（归一前落盘，读时自动归一）：

```text
ts_code,trade_date,open,high,low,close,vol,amount
510300.SH,20200102,4.12,4.17,4.11,4.14,6276236,2603983
```

- `trade_date` 为 `YYYYMMDD` 字符串；
- 框架读数据时经 `DataNormalizer` 统一成内部 K 线（设计 3.3），所以落盘保持源格式即可。

## 4. 第 2 步：下载 ETF / LOF 日线

核心命令（完整 DataFetcher 六步管道，幂等/去重/原子写）：

```bash
.venv/Scripts/python -m mtzquant fetch \
  --codes 510300.SH,510500.SH,159915.SZ \
  --start 2020-01-01 --end 2026-08-16 \
  --sources tushare
```

### 4.1 参数说明

| 参数 | 必填 | 说明 |
|------|------|------|
| `--codes` | 是 | 逗号分隔代码。支持 `510300.SH` / `510300.XSHG` / `159915.XSHE`（聚宽后缀自动归一）等写法 |
| `--start` / `--end` | 是 | 区间 `YYYY-MM-DD`；`--end` 想截止今天可写今天日期 |
| `--sources` | 否 | 逗号分隔源，顺序=fallback。默认 `akshare,tushare`；**只用 tushare 写 `tushare`** |
| `--freq` | 否 | 仅 `1d`（分钟线 M5 才支持） |
| `--resume` | 否 | 续传：已 checkpoint 的区间不重下（大区间/断网恢复用） |
| `--dry-run` | 否 | 只做覆盖检查不下载不写盘 |
| `--master` | 否 | 只刷新主数据（全量拉取 + code 主键 upsert） |

### 4.2 它自动帮你做的事（为什么不会下坏）

1. **幂等**：已有数据先做覆盖检查，已覆盖区间直接 `skipped`，重复跑零请求零写入；
2. **切片续传**：大区间按年切片 + checkpoint（`.cache/fetch_checkpoint/`），断网后 `--resume` 不重下；
3. **去重合并**：新数据与旧 CSV 按 `trade_date` 去重（keep=latest）后再写盘；
4. **落盘断言**：写入前校验日期唯一、可解析、OHLCV 非空，不合格拒绝写盘；
5. **原子写**：临时文件 + `os.replace`，中断不损坏已有 CSV；
6. **防封禁**：令牌桶限流 + 指数退避重试 + 连续失败熔断。

### 4.3 常见用法示例

```bash
# ① 只下几只（演示用）
.venv/Scripts/python -m mtzquant fetch --codes 510300.SH --start 2020-01-01 --end 2026-08-16 --sources tushare

# ② 下整批组合（多只）
.venv/Scripts/python -m mtzquant fetch \
  --codes 510310.SH,513500.SH,510210.SH,159903.SZ,159901.SZ,510180.SH,511260.SH,160719.SZ,165513.SZ \
  --start 2020-01-01 --end 2026-08-16 --sources tushare

# ③ 先看缺哪些（不下载）
.venv/Scripts/python -m mtzquant fetch --codes 510300.SH --start 2020-01-01 --end 2026-08-16 --sources tushare --dry-run

# ④ 只刷新主数据清单
.venv/Scripts/python -m mtzquant fetch --master --sources tushare
```

> 输出即报告：每只 `code / status(ok|skipped|failed) / 新增行 / 去重 / 区间 / 来源 / 原因`，加 `--json` 可机读。

## 5. 第 3 步：下载指数（基准）日线

**注意**：指数**不是基金**，tushare 走 `pro.index_daily` 而非 `fund_daily`；框架的 `fetch` 命令目前没有 index_daily 分支，
需要一次性小脚本单独落盘到 `data/kline/index/day/{code}.csv`。

```python
# download_index.py（一次性脚本，可放 .cache/ 或临时目录，不提交）
from pathlib import Path
import tushare as ts
import pandas as pd
from mtzquant.config import get_tushare_token, load_secrets
from mtzquant.data.master import InstrumentRow, MasterStore

CODE, START, END = "000300.SH", "20200101", "20260816"
COLS = ("ts_code", "trade_date", "open", "high", "low", "close", "vol", "amount")

pro = ts.pro_api(get_tushare_token(load_secrets()))
raw = pro.index_daily(ts_code=CODE, start_date=START, end_date=END)
raw = raw[list(COLS)].sort_values("trade_date").reset_index(drop=True)
assert len(raw) == raw["trade_date"].nunique()          # 日期唯一
assert raw[["open", "high", "low", "close", "vol", "amount"]].notna().all().all()

path = Path("data/kline/index/day") / f"{CODE}.csv"
path.parent.mkdir(parents=True, exist_ok=True)
path.write_text(raw.to_csv(index=False), encoding="utf-8")

MasterStore(Path("data/master/instruments.csv")).upsert([
    InstrumentRow(code=CODE, name="沪深300指数", instrument_type="index", exchange="SH")
])
```

关键点：

- **列序必须对齐 tushare 源格式**：`ts_code, trade_date, open, high, low, close, vol, amount`（`index_daily` 返回的 close/open 顺序与源格式不同，须重排）；
- **目录必须用 `index/`**：引擎读基准时按 `ETF → 股票 → 指数` 跨目录探测（`csv_driver.py:53`），放 `kline/index/day/` 才能被当基准消费；
- master 行 `instrument_type=index`，指数不可交易（基准/对比用）。

## 6. 第 4 步：日常增量更新

同一命令把 `--end` 改为最新交易日即可——覆盖检查自动只补缺失段：

```bash
.venv/Scripts/python -m mtzquant fetch --sources tushare \
  --codes <你的代码清单> --start 2020-01-01 --end <最新交易日>
```

> 指数 000300 的增量更新需重跑 §5 脚本（把 END 改成最新日期即可）。

## 7. 第 5 步：验证数据没问题

### 7.1 快速质量体检（重复日期 / 坏日期 / 空值）

```bash
.venv/Scripts/python - <<'PY'
from pathlib import Path
import pandas as pd
for p in sorted(Path("data/kline").rglob("*.csv")):
    df = pd.read_csv(p, dtype={"trade_date": str})
    dup = int(df["trade_date"].duplicated().sum())
    bad = int(pd.to_datetime(df["trade_date"], errors="coerce").isna().sum())
    nulls = int(df[["open","high","low","close","vol","amount"]].isna().sum().sum())
    print(f"{p:45s} rows={len(df):5d} dup={dup} bad={bad} null={nulls}")
PY
```

期望输出：`dup=0 bad=0 null=0` 全部为 0。

## 8. 常见问题排查

| 现象 | 原因 / 处理 |
|------|-------------|
| `tushare token 缺失` | 没配 `secrets.json` 或环境变量，见 §2.2 |
| `基金代码拉取失败 / 空数据` | 代码写错或未上市（如 515790 2020-12 才上市，2020 年初无数据是正常的）；确认代码后缀 `.SH/.SZ` |
| `接口限流` | tushare 按积分限频；稍等重跑即可（`--resume` 续传不重复下已完成的切片） |
| 想下全市场几百只 ETF | 先 `--master --sources tushare` 拉主数据清单，再循环 `fetch`；受限流约束耗时较长 |
| 指数下不下来 | 必须用 `index_daily` 单独脚本（§5），`fetch` 命令不支持 |
| 数据格式/日期报错 | 确认文件是 tushare 源格式列序（§3），`trade_date` 为 `YYYYMMDD` |
