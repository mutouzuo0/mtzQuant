# mtzQuant 使用说明

> 本地优先 · 事件驱动 · 多策略平台兼容的量化回测框架。
> 本文档覆盖：**怎么运行** → **怎么准备数据** → **怎么用 AI 干活**。
> 当前进度：M0+M1 可信日线内核、M2 平台适配（native/joinquant/ptrade）、M4 最小 Web 可视。

---

## 1. 环境与安装

- Python **≥ 3.11**（项目 `requires-python` 硬性要求）
- 依赖：pandas / SQLAlchemy2 / Alembic / fastapi / uvicorn / duckdb / typer 等（`pyproject.toml`）

```bash
python -m venv .venv

# Windows
.venv/Scripts/pip install -e ".[dev]"

# Linux / macOS
source .venv/bin/activate && pip install -e ".[dev]"
```

> 装完后可用两种方式调 CLI：激活 venv 后直接 `mtzquant ...`，
> 或不经激活 `python -m mtzquant ...`（本仓库习惯用后者，下文统一写 `mtzquant`）。

### 1.1 初始化配置

```bash
cp config/settings.example.json config/settings.json    # 本地配置（不入 Git）
cp config/secrets.example.json   config/secrets.json    # 密钥（不入 Git）
# 打开 secrets.json，填入 tushare token（用于在线下载数据）
mtzquant config                                           # 检查配置状态
```

> 注意：命令是 `mtzquant config`（不是 `config check`）。检查项：
> `settings.json` 缺失时自动用内置默认值；`secrets.json` 决定在线源是否可用。

`settings.json` 关键段落（全部可改）：

| 段落 | 作用 | 常用键 |
|------|------|--------|
| `data.local_csv` | 本地 CSV 目录布局 | `root_path`(默认 `./data`)、`encoding`、`adjust` |
| `data.download` | 下载限流/去重 | `rate_limit_per_min`、`dedup_keep` |
| `data.cache` | 二级 parquet 缓存 | `enabled`、`parquet_dir` |
| `database.url` | 业务库 | 默认 `sqlite:///./mtzquant.db` |
| `engine` | 撮合默认值 | `fill_price`、`slippage`、`default_fees`、`max_participation`、`random_seed` |

## 2. 三分钟跑通（快速开始）

```bash
# ① 一键准备演示数据：3 只主流 ETF 2020 至今（幂等/去重/原子写）
mtzquant fetch-etf --demo

# ② 校验任务配置（pydantic 全字段）
mtzquant validate -c configs/demo_dual_ma.json

# ③ 跑一次回测（会话装配 → 引擎驱动 → 导出 → DB 入库）
mtzquant run -c configs/demo_dual_ma.json

# ④ 看结果
mtzquant list                          # 历史回测记录
mtzquant report <run_id>               # 生成 results/<run_id>/report.html
mtzquant serve --with-task configs/demo_dual_ma.json   # Web 实时可视，浏览器开 127.0.0.1:8501
```

一次完整 `mtzquant run` 会产出：
- **业务库入库**（`mtzquant.db`）：参数 / 策略快照 / 订单 / 成交 / 逐日净值 / 指标（物理 FK，可复现）；
- **报告**：`mtzquant report <run_id>` → 自包含 `report.html`（指标卡 / 语义保真 / 净值+回撤 SVG / 成交表）。

## 3. 运行回测

### 3.1 任务配置 JSON（唯一事实来源）

一个任务 = 一份 JSON。示例 `configs/demo_dual_ma.json`：

```jsonc
{
  "task_name": "demo_dual_ma",            // 任务名（list/report 展示用）
  "strategy": {
    "file": "strategies/native/dual_ma.py", // 策略源码路径（相对仓库根或绝对路径）
    "type": "native",                       // 平台适配器：native | joinquant | ptrade
    "entry": "on_bar"                       // native 入口回调名
  },
  "backtest": {
    "start": "2020-01-01",                  // 回测开始日
    "end": "2025-12-31",                    // 回测结束日
    "initial_capital": 1000000,             // 初始资金
    "benchmark": "510300.SH",               // 基准（生成 benchmark_nav）
    "frequency": "1d",                      // 目前仅 1d
    "initial_positions": {},                // 初始持仓 code → qty
    "strict_schedule": false                // 严格调度（不支持的调度直接拒绝 vs 降级）
  },
  "universe": ["510300.SH"],                // 股票池（归一代码）
  "fees": {                                 // 覆盖默认费率（可省略，用 settings 默认）
    "commission_rate": 0.0001,
    "min_commission": 5.0,
    "stamp_tax_rate": 0.0,
    "transfer_fee_rate": 0.0
  },
  "engine": {}                              // 撮合覆盖项（预留）
}
```

必填：`task_name`、`strategy.file`、`backtest.start/end`、`universe`。
完整 schema：`docs/schema/task.schema.json`（JSON Schema，可交给编辑器/AI 校验）。

### 3.2 三种平台策略写法

仓库内三份现成示例，可直接复制改：

| 平台 | `strategy.type` | 代码风格 | 示例 |
|------|-----------------|----------|------|
| **native** | `native` | `initialize(context)` + `on_bar(context, bar)`；`context.g[...]`、`context.history(code, n)`、`context.account.positions`、`context.adapter.order_target_value` | `strategies/native/dual_ma.py` |
| **joinquant**（聚宽） | `joinquant` | 官方聚宽风格零改动：`initialize` / `handle_data(context,data)` / `before_trading_start` / `after_trading_end`；`g.x`、`set_universe`、`attribute_history`、`order_target_value`、`run_daily`；代码用 `.XSHG/.XSHE`（自动归一） | `strategies/joinquant/dual_ma.py` |
| **ptrade** | `ptrade` | 官方 PTrade 风格零改动：`initialize` / `handle_data` / `run_daily(func, context, '09:30')` | `strategies/ptrade/demo_all_weather.py` |

> joinquant/ptrade 为 M2 适配器：支持官方 API 子集（数据族 / 下单族 / 调度族 / 配置族），
> 不支持的 API 抛结构化 `NotImplementedApiError`（带 `level` + `alternative` 替代建议），
> 语义近似的操作记 `semantic_degradation`（run 状态 `completed_degraded`）。
> 各平台支持范围见 `docs/compat/joinquant.md`、`docs/compat/ptrade.md`。

### 3.3 CLI 全部子命令

```bash
mtzquant config                 # 检查配置（settings/secrets 状态）
mtzquant validate -c <task>     # 校验任务 JSON
mtzquant run -c <task>          # 跑回测（[--isolate] 子进程隔离 / [--json] 机读输出）
mtzquant list [--sort] [--limit]# 历史记录
mtzquant report <run_id>        # 生成 report.html
mtzquant replay                 # 按 RunManifest 重放并 diff（逐笔订单/成交/逐点净值/manifest_hash）
mtzquant compare                # 多 run 指标对照表 + 净值对齐（--csv 导出）
mtzquant lineage                # run 谱系树（parent_run_id）
mtzquant diff                   # 策略源码 + 参数（归一）差异
mtzquant rerun                  # params_json 原样重跑，新 run 挂 parent
mtzquant fetch                  # 下载 K 线/主数据（见 §4.1）
mtzquant fetch-etf              # 下载 ETF 日线（--demo 一键演示数据）
mtzquant sql "<SELECT ...>"     # DuckDB 只读即席查询（写面语句拒绝）
mtzquant cache --all            # 清理 parquet 二级缓存
mtzquant serve [--with-task]    # Web 最小可视版（127.0.0.1:8501）
```

### 3.4 程序化调用（Python API）

不想走 CLI 时，可按测试链路手动装配（真实 BrokerSim）：

```python
from mtzquant.engine.engine import UnifiedBacktestEngine
from mtzquant.engine.results import ResultStore
from mtzquant.engine.runner import _settings_fees, build_pipeline
from mtzquant.engine.session import BacktestSession

env = ...                       # 含 task / settings（tests/fixtures/backtest_env.py 是模板）
pipeline = build_pipeline(env.settings, env.task.universe)
session = BacktestSession(
    env.task, driver=pipeline.driver, provider=pipeline.provider,
    calendar=pipeline.calendar, run_id="r1",
    settings_fees=_settings_fees(env.settings), result_store=ResultStore(run_id="r1"),
)
snapshot = UnifiedBacktestEngine(session, broker=session.broker).run()
```

## 4. 准备数据

数据只落在 `data/`（不入 Git）。两条路：**在线自动下载** 或 **手工 DIY CSV**。

### 4.1 方式 A：在线下载（推荐，最省事）

```bash
# K 线 + 主数据（多源 fallback：akshare → tushare，顺序=优先级）
mtzquant fetch \
  --codes 510300.SH,600000.SH,159915.SZ \
  --start 2020-01-01 --end 2025-12-31 \
  --sources akshare,tushare

# 刷新主数据（master 全量拉取 + code 主键 upsert + 快照留档）
mtzquant fetch --master

# 一键 ETF 演示数据（3 只主流 ETF 2020 至今）
mtzquant fetch-etf --demo
# 或指定 ETF
mtzquant fetch-etf --codes 510300.SH,510500.SH --start 2020-01-01 --end 2025-12-31

# 导入任意目录的 CSV（自动嗅探格式 → 去重合并 → 入库）
mtzquant fetch --import <some_dir>
```

下载走「六步管道」：覆盖检查 → 增量 → 归一校验 → DuckDB 去重 → 原子落盘 → 缓存失效；
带限流令牌桶 + 重试 + 熔断（`--resume` 可续传）。

> 在线源需要网络；tushare 需要 token（`config/secrets.json`）。

### 4.2 方式 B：手工 DIY CSV

目录约定（设计 3.12，`settings.json` 可改路径模板）：

```
data/
├── master/instruments.csv              # 标的主数据
├── kline/{etf,stock}/day/{code}.csv    # 日线（归一代码命名：510300.SH.csv）
├── corporate_actions/{type}/{code}.csv # 公司行为（announce/ex/pay 三日期）
├── calendars/trade_days.csv            # 交易日历
└── factor/adj_factor/{type}/{code}.csv # 复权因子
```

**代码命名（归一）**：`510300.SH`（沪）/ `600000.SH`（沪股）/ `159915.SZ`（深）。
聚宽风格 `.XSHG/.XSHE` 会自动归一；K 线文件名必须用归一代码。

**K 线 CSV 三种格式**（读取时自动嗅探前 5 行，`settings.format` 可显式指定）：

| 格式 | 列 |
|------|-----|
| tushare | `ts_code, trade_date(YYYYMMDD), open, high, low, close, vol, amount` |
| joinquant | `time, open, high, low, close, volume, money, paused, factor` |
| generic | `date, time, open, high, low, close, volume, amount` |

一个最简单的合法 K 线文件（tushare 格式，`data/kline/etf/day/510300.SH.csv`）：

```csv
ts_code,trade_date,open,high,low,close,vol,amount
510300.SH,20200102,3.8000,3.8500,3.7900,3.8400,10000000,38400000.00
510300.SH,20200103,3.8400,3.9000,3.8300,3.8900,12000000,46680000.00
```

> 要求：日期升序、无重复时间戳、币种单位一致。OHLC 缺失按 `pre_close` 沿用、
> `volume/amount` 缺失按 0、全空行按停牌处理。

**交易日历** `data/calendars/trade_days.csv`：单列日期（`YYYY-MM-DD`），
列名 `date` / `cal_date` / `trade_date` 均自动识别。缺省时框架可从 K 线推导回写。

**主数据** `data/master/instruments.csv`：列含 `ts_code/name/list_date` 等（tushare 风格）。

> 手工造演示数据可用测试里的合成器为模板：`tests/fixtures/synth.py::flat_etf_csv`
> （价格恒定 → 净值可手算，方便校验）。

### 4.3 数据质量体检

```bash
# DuckDB 只读即席查询（写面语句一律拒绝）
mtzquant sql "SELECT code, count(*) AS bars FROM kline GROUP BY code"
```

更全面的质量模板（缺失交易日 / 0 价 0 量 / OHLC 越界 / 重复日期 / 日期解析失败）
见 `mtzquant/data/` 的 `DuckDBQuery.quality_report`（§5 数据源开发指南）。

## 5. 怎么用 AI

本框架从设计上就对 **AI 编码助手友好**，常见用法有四类。

### 5.1 AI 驱动项目开发（本会话模式）

AI 助手（如 Claude/Codex/Cursor/ZCode 等）作为「结对开发者」推进功能：

1. **喂上下文**：AI 先读 `AGENTS.md`（用户级 + 仓库级，含硬性规范与门禁命令）、
   `.zcode/mtzQuant回测框架设计方案.md`（架构全文，不入库）、`.zcode/plans/*.md`（实施计划）；
2. **下任务**：给 AI 一句话需求（如「新增 XX 数据源」「适配 XX 平台 API」）；
3. **AI 实现**：遵循依赖契约（import-linter）、文件头注释规范、确定性纪律（seed=42）；
4. **AI 自检**：提交前必须过全套门禁——
   ```bash
   pytest                      # 快速门禁（387+ 用例）
   ruff check mtzquant tests && ruff format --check mtzquant tests
   mypy mtzquant
   lint-imports                # 适配器不得依赖引擎内部
   ```
5. **黄金用例**：AI 改撮合/记账行为时，按「六要素」（订单/成交/现金/持仓/费用/净值）
   逐笔断言（`tests/golden/`），禁止只看最终收益。

### 5.2 AI 编写 / 移植策略

- 直接让 AI 按 §3.2 三平台风格产出策略源码，放 `strategies/<platform>/`；
- 平台 `detect()` 能自动嗅探一段策略代码属于 native / joinquant / ptrade，
  可让 AI 生成代码后交给 `_default_registry.detect()` 复核；
- **聚宽/PTrade 官方策略可零改动本地回测**——把线上代码原样放进任务 JSON
  （`type: "joinquant"/"ptrade"`），M2 适配器负责翻译，AI 不需要改业务逻辑；
- AI 改完策略后用 `mtzquant replay` 验证与基准逐笔一致（`manifest_hash` 指纹比对）。

### 5.3 AI 准备 / 清洗数据

- 让 AI 按 §4.2 格式生成或改写 CSV（框架对未知格式报错时**会列出期望列清单**，AI 可对照修）；
- 批量清洗：AI 生成脚本 → `mtzquant fetch --import <dir>` 统一入库（嗅探/去重/原子写）；
- 数据体检：`mtzquant sql "SELECT ..."` 让 AI 查缺口、0 价 0 量、重复日期。

### 5.4 AI 友好特性速查

| 特性 | 说明 |
|------|------|
| 结构化错误 | `MtzQuantError` / `NotImplementedApiError` 带 `run_id/stage/hint`，hint 面向 AI 修复 |
| CLI `--json` | 所有命令可机读输出，AI 直接解析 |
| 未知格式报错列清单 | CSV 列名不符时报出期望列，AI 对照修补 |
| `detect()` | 策略平台自动嗅探 |
| `replay` / `diff` / `manifest_hash` | AI 迭代后验证行为一致性（防回归） |
| `compare` / `lineage` / `rerun` | AI 调参研究：指标对照 + 谱系树 + 原样重跑 |

## 6. 常见问题 FAQ

| 问题 | 答案 |
|------|------|
| `mtzquant` 命令找不到 | venv 未激活；用 `.venv/Scripts/python -m mtzquant ...`（Windows） |
| 没准备数据就跑 | 报缺 K 线 → 先 `mtzquant fetch-etf --demo` 或按 §4 DIY |
| 在线下载失败 | 检查网络与 `secrets.json` 的 tushare token；`--sources akshare,tushare` 多源 fallback |
| 回测结果在哪 | `results/<run_id>/report.html` + `mtzquant.db`（SQLite，可切 PostgreSQL） |
| 复权价会不会进撮合 | 不会。`raw_price` 是唯一记账/撮合基准，复权价只用于指标研究（设计 3.14 纪律） |
| 结果能复现吗 | 能。RunManifest 记录代码/数据/环境全版本指纹，同 manifest 重放逐笔一致 |
| 想加新数据源 | 见 `docs/数据源开发指南.md`（实现 `RemoteKlineSource` 协议 + 注册 + 限流登记） |
| 想加新平台适配 | 见 `docs/适配器开发指南.md` |

## 8. 纪律与安全（提交/协作必读）

- **不入库清单**：`config/secrets.json`、`config/settings.json`、`data/`、`results/`、`.cache/`、`mtzquant.db*`、`.zcode/`；
- **密钥纪律**：token/key 只进 `config/secrets.json`（已 gitignore）或 `MTZQUANT_*` 环境变量；代码/文档一律占位符；
- **确定性**：禁止未播种随机（`random_seed=42`）；dict 遍历先排序；时间戳整数毫秒；
- **测试通过才能提交**：提交前跑完 §5.1 全套门禁。
