🚀 快速上手（三步跑通第一个回测）

  1. 准备策略：把 .py 策略放进 strategies/<平台>/，或在「新建回测」页直接「上传本地 .py」；
  2. 配置任务：「新建回测」页选平台 / 策略 / 区间，点「提交回测」；
  3. 看结果：自动跳转「监控」页看实时进度与净值；完成后到「历史」页点「报告」看完整回测报告。

❓ 常见问题

  • 状态「完成·降级」是什么？ 回测跑完但有部分数据缺失或适配器降级（如某标的停牌段数据不足），结果仍完整可用，详情见报告中的降级清单。
  • 历史页指标是「—」？ 该 run 尚未写入绩效指标（如运行中，或由旧版引擎产生）。运行中请在监控页等完成；旧 run 可在报告页重跑后得到指标。
  • 数据下载「检查覆盖」和「确认下载」区别？ 检查只读本地估算缺口，不联网；确认后才联网补齐缺失区间。
  • 连接状态徽章？ 「已连接」= 与回测服务的实时通道正常；「已断开，重连中…」= 网络抖动自动重连；「连接失败」= 服务未启动或异常。
开发者附录（内部约定, 普通用户可忽略）
  • 事件流信封: {type, run_id, ts, event_seq, committed, data}，断线按 event_seq 补帧（resume 协议）;
  • 子进程隔离执行回测（serve 父进程不加载策略代码）; 认证: server.auth_enabled + secrets server.tokens;
  • 报告与 mtzquant report <run_id> 同一自包含 report.html（CLI / Web / Python API 三面同权）。
回测结束后可在「历史 → 报告」直接查看完整 Web 报告（等价于命令行 mtzquant report <run_id>）。
